# Decision Tree Split — Phishing URL Classification

This project explores a Gini-based decision-tree split for identifying phishing URLs. The existing `main.py` contains the original split-search work. The separate `evaluate.py` script tests the best root split on a held-out dataset and reports classification metrics with visualizations. It does not modify or run `main.py`.

## Project Structure

```text
decision tree/
├── phishing_site_urls.csv       # URL records labeled bad/good
├── main.py                      # Original decision-tree split experiment
├── evaluate.py                  # Test-set metrics and visualization script
├── readme.md                    # Project documentation
└── decision_tree_evaluation.png # Generated by evaluate.py
```

The PNG is created when `evaluate.py` runs.

## Evaluation Workflow

`evaluate.py` performs these steps independently:

1. Reads the CSV beside the script and converts `bad` to phishing (1) and `good` to legitimate (0).
2. Extracts the same numeric URL features as the original script: URL and host lengths, punctuation and digit counts, IP-address indicator, HTTPS indicator, subdomain count, suspicious-word count, and port indicator.
3. Splits the data into 80% training and 20% test subsets. The split is stratified and uses a fixed random seed.
4. Finds the training-set feature and threshold with the lowest weighted Gini impurity. The two resulting leaves predict their training-set majority class.
5. Evaluates predictions on the held-out test set and saves an evaluation dashboard.

The evaluation script measures the **best single root split (decision stump)**, not a recursively grown multi-level tree. It is an evaluation companion for the current split-search work.

## Gini Impurity

For class proportions $p_0$ and $p_1$, node impurity is:

$$
G = 1 - p_0^2 - p_1^2 = 2p_0p_1
$$

A candidate feature threshold divides the training data into left and right groups. Their weighted impurity is:

$$
G_{weighted} = \frac{n_L}{n}G_L + \frac{n_R}{n}G_R
$$

The split search selects the threshold with the smallest weighted impurity.

## Metrics and Plots

The script prints **accuracy**, **precision**, **recall**, **F1-score**, **ROC-AUC**, and a classification report. The positive class is phishing (`bad`).

The saved `decision_tree_evaluation.png` contains:

- Confusion matrix for legitimate and phishing predictions.
- Metric score bars.
- ROC curve using the phishing rates of the two leaves as prediction scores.
- Training-sample counts in the two branches, broken down by class.

For phishing detection, recall indicates how many phishing samples were found; precision indicates how many flagged samples were phishing. Metrics are specific to this held-out split and do not guarantee real-world detection performance.

## Requirements

Install dependencies in the active Python environment:

```bash
python -m pip install numpy pandas matplotlib scikit-learn
```

## Run Evaluation

From the repository root:

```bash
python "decision tree/evaluate.py"
```

Or from this directory:

```bash
python evaluate.py
```

For a headless environment:

```bash
MPLBACKEND=Agg python evaluate.py
```

The report is printed in the terminal, and the dashboard is saved beside the script. The project dataset has over half a million rows, so feature extraction and split search may take some time.

## Data Expectations and Limitations

- The CSV requires `URL` and `Label` columns; labels should be `bad` or `good` (case-insensitive).
- Rows with a missing URL or label are skipped during evaluation.
- URL heuristics only use the address text. They do not inspect website content, certificates, redirects, or linked pages.
- A single split is intentionally shallow and should not be treated as a production anti-phishing system.
